## 🚀 خطوات التشغيل

### 1) أنشئ مشروع Firebase
اذهب إلى https://console.firebase.google.com → Add project.

### 2) فعّل الخدمتين
- **Authentication** → Sign-in method → فعّل "Email/Password".
  ثم من تبويب Users أضف مستخدم أدمن يدوياً (إيميل + باسورد) عشان تسجل دخول بيه في `index.html`.
- **Realtime Database** → Create Database → اختر أي Location قريب منك، وابدأ في وضع Test mode مبدئياً (وبعدين حط الـ Rules تحت).

### 3) هات إعدادات المشروع
من ⚙️ Project settings → General → Your apps → اختر Web app (</>) → هيديك object زي ده:
```js
const firebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  databaseURL: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```
انسخه وحطه في ملف **`js/firebase-config.js`** مكان القيم الموجودة.

### 4) Realtime Database Rules (مهم جداً - محدّثة)
من تبويب Realtime Database → Rules، حط الآتي:

```json
{
  "rules": {
    "students": {
      ".read": true,
      ".write": "auth != null",
      "$code": {
        "attendance": { ".write": true },
        "notes": { ".write": "auth != null" }
      }
    },
    "teachers": {
      ".read": true,
      ".write": "auth != null"
    },
    "paymentRequests": {
      ".read": "auth != null",
      ".write": true,
      ".indexOn": ["status"]
    },
    "presence": {
      ".read": true,
      ".write": true
    },
    "stats": {
      ".read": "auth != null",
      "pageViews": { ".write": true }
    },
    "systemBackups": {
      ".read": "auth != null",
      ".write": "auth != null"
    }
  }
}
```
> ملحوظات أمان:
> - `students.read: true` عشان أي حد معاه رابط أو QR الطالب يقدر يفتح بروفايله من غير تسجيل دخول.
> - `paymentRequests.write: true` لازم تكون مفتوحة عشان الطالب (اللي مسجلش دخول) يقدر يبعت طلب دفع، بس القراءة والموافقة مقصورة على الأدمن.
> - `presence` و `stats/pageViews` مفتوحة للقراءة/الكتابة لأنها مجرد عدادات لحظية بسيطة مفيش فيها بيانات حساسة.
> - `systemBackups` مقصورة على الأدمن بس (قراءة وكتابة) لأنها بتحتوي على نسخة كاملة من كل بيانات الطلاب الحساسة.
> - لو عايز حماية أقوى (مثلاً منع أي حد يعدّل طلب دفع غير بتاعه) ده محتاج Firebase Cloud Functions أو Security Rules أكثر تعقيداً - قوللي لو عايز الإصدار المحمي أكتر.

### 4.b) Firebase Storage (لصور إثبات الدفع - اختياري لكن مفضّل)
من Firebase Console → Build → Storage → Get started، وحط الـ Rules دي:
```
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /payment-proofs/{fileName} {
      allow read: if request.auth != null;
      allow write: if true;
    }
  }
}
```
لو مش عايز تفعّل Storage خالص، مفيش مشكلة - المشروع بيرجع تلقائياً يخزن الصورة كـ Base64 جوه الـ Database (شغال بس مش الأفضل لصور كبيرة/كتيرة).

### 5) شغّل المشروع
المشروع كله ملفات static عادية، تقدر:
- تفتحه مباشرة بمتصفح (بس الكاميرا/QR Scanner محتاجة `https` أو `localhost` عشان تشتغل).
- أو تستخدم إضافة Live Server في VS Code.
- أو ترفعه على **Firebase Hosting** (الأسهل، ومجاني):
  ```bash
  npm install -g firebase-tools
  firebase login
  firebase init hosting
  firebase deploy
  ```

## ✅ الصفحات والوظائف

### `index.html` — تسجيل دخول الأدمن
دخول بإيميل وباسورد (Firebase Auth) فقط.

### `admin.html` — لوحة تحكم الأدمن (8 تابات)
1. **الرئيسية**: عدد الطلاب الكلي، متصلين بالموقع الآن (Presence)، عدد مرات فتح الموقع، حضروا النهاردة، عدد الدافعين/الغير دافعين الشهر ده، طلبات الدفع الأونلاين المعلقة، وزرار "كل الطلاب" (قائمة بكل الأسماء والأكواد قابلة للبحث، بتودّيك على تبويب التعديل مباشرة لو ضغطت على طالب).
2. **إنشاء طالب جديد**: اسم + صف + **رقم واتساب ولي الأمر** + مواد. تقدر تختار "مدرس" و"مجموعة" من قايمة جاهزة فتتعبى المادة/الأيام/الميعاد/المصاريف تلقائياً، أو تكتبهم يدوي.
3. **المدرسين**: أضف مدرس، وأضف له مجموعات (اسم + أيام + ميعاد + مصاريف) - وكل مجموعة بتوريك عدد الطلاب المسجلين فيها تلقائياً (بيتحسب من بيانات الطلاب).
4. **إضافة درجات (3 مربعات)**: كود → بحث → اسم الطالب يظهر تلقائي للتأكيد → إدخال اسم الامتحان والدرجة → حفظ في سجل الطالب.
5. **تعديل بروفايل طالب**: بحث بالكود → تعديل كل البيانات (الاسم / رقم ولي الأمر / المواد) أو حذف الطالب.
6. **الحضور والانصراف**: 3 طرق للتسجيل مع بعض:
   - مربع إدخال يدوي للكود (ده نفسه بيشتغل مع **قارئ الباركود المتوصل بالكمبيوتر (USB)** لأنه بيتعامل معاه زي الكيبورد بالظبط - بس اضغط جوه المربع وامسح الكارت).
   - كاميرا لقراءة QR Code.
   - النظام "ذكي": بيرفض تسجيل الحضور لو مفيش معاد للطالب دلوقتي (بيقارن الوقت الحالي بمواعيد مواده المسجلة بهامش 20 دقيقة)، وبيرفضه لو الطالب لسه ما دفعش مصاريف الشهر (مع إمكانية للأدمن يسجّل يدوياً رغم كده لو حابب).
   - قسم "فاتهم معادهم النهاردة": بيوريك أي طالب فات معاده بأكتر من 15 دقيقة من غير ما يسجل حضور، مع زرار يفتحلك واتساب برسالة جاهزة لولي الأمر.
7. **المصروفات**: دور بكود الطالب، هتلاقي كل المواد وسعرها مع زرار ✓ / ✗ لتأكيد الدفع لشهر معين (وبيبعت تأكيد واتساب لولي الأمر أوتوماتيك لما تعمل ✓). وتحت كده "طلبات الدفع الأونلاين" اللي بيبعتها الطلاب (بالصورة ورقم التليفون) عشان تراجعها وتوافق عليها.
8. **ملاحظات**: دور بكود الطالب، اكتب ملاحظة (زي "الطالب مشاغب النهاردة")، اضغط إرسال → بتتحفظ في بروفايل الطالب وبيتفتحلك واتساب برسالة جاهزة لولي الأمر.

### `student.html?id=CODE` — بروفايل الطالب (عام، بدون تسجيل دخول)
يفتح تلقائياً ببيانات الطالب صاحب الكود: الملف الشخصي، **المصروفات** (حالة كل مادة الشهر ده + زرار "دفع أونلاين" بيفتح مودال فيه رقم فودافون كاش/بيانات البنك، ورفع صورة إثبات التحويل ورقم الهاتف، والطلب بيروح لوحة الأدمن للمراجعة)، الإمتحانات (بجراف)، الحضور والغياب (بجراف)، التحليل العام، **الملاحظات** (يشوف فيها كل الملاحظات اللي بعتها الإدارة)، وتقرير يومي سريع.

## 📱 بخصوص إرسال واتساب التلقائي - مهم توضيحه
من متصفح عادي (بدون سيرفر backend أو اشتراك في WhatsApp Business API المدفوع من ميتا)، **مستحيل تقنياً** إرسال رسالة واتساب فعلياً بدون أي تدخل من حد. اللي المشروع بيعمله هو أقصى حاجة ممكنة client-side:
كل عملية (حضور/انصراف/دفع/ملاحظة/تنبيه غياب) بتفتح رابط `wa.me` **معبّى برقم ولي الأمر ونص الرسالة جاهز**، وانت (الأدمن) بس تضغط "إرسال" في واتساب. لو عايز إرسال أوتوماتيك 100% بدون ما حد يضغط أي حاجة، ده محتاج:
- سيرفر Backend (زي Firebase Cloud Functions) يشتغل في الخلفية.
- اشتراك في WhatsApp Business API (عن طريق Twilio أو Meta مباشرة) - عادةً بيبقى بفلوس لكل رسالة.
قوللي لو عايز نضيف الجزء ده بعدين.

## ⏰ بخصوص "الغياب التلقائي" لما ييجي يوم 1 في الشهر أو لما يعدي معاد الحصة
برضو ده محتاج **مجدول (Scheduler / Cron Job)** يشتغل في الخلفية حتى لو محدش فاتح الموقع - وده مش متاح في موقع static عادي، لازم Firebase Cloud Functions + Cloud Scheduler (فيها تكلفة بسيطة على خطة Blaze في فايربيز). البديل المتاح دلوقتي في المشروع: قسم "فاتهم معادهم النهاردة" و"عدد الدافعين/الغير دافعين" بيتحسبوا **لحظة ما تفتح لوحة الأدمن**، وانت اللي بتضغط "إرسال تنبيه" يدوياً لكل حالة.

## 🆕 التحديث الجديد (مراجعة شاملة) - ملخص كل حاجة اتضافت

⚠️ **كل الـ APIs / مسارات قاعدة البيانات القديمة اتسابت زي ما هي بدون أي تعديل أو حذف.** كل التالي إضافات جديدة فوق البنية القديمة.

### إصلاح مهم
- **إصلاح باج "المدرسين ما بيظهروش إلا بعد إنشاء مدرس جديد"**: أي قائمة "اختر مدرس" ظاهرة على الشاشة بقت تتحدث فوراً بمجرد ما بيانات المدرسين تتغيّر (بدل ما تفضل قديمة لحد ما تضيف صف جديد).
- **إصلاح باج تعطيل عداد "متصل الآن" و"عدد مرات الفتح" في صفحة الطالب**: كان فيه تعريف وهمي زيادة بيلغي الأصلي بالغلط، اتشال.

### 1) الإحصائيات
- عداد "فتح الموقع آخر 24 ساعة" (سجل زمني `stats/pageViewsLog`) + عداد "زوار عبر رابط مباشر" (`stats/directTraffic`) - بجانب الإجمالي القديم اللي فضل شغال زي ما هو.
- تبويب جديد "👥 عدد الطلاب بالمجموعة": بيوري كل مدرس ومجموعاته ومواعيدها + عدد الطلاب الكلي بكل مجموعة (بيزيد أوتوماتيك) + عدد حضور اليوم (بيتصفر كل يوم من نفسه لأنه بيتحسب من تاريخ اليوم فقط). "إجمالي الطلاب الكلي" (عدد عناصر `students/`) ثابت ولا يتصفر ولا يتكرر لأنه معتمد على وجود الطالب مش على تسجيلات الحضور.

### 2) الطلاب والمدرسين
- شاشة "تعديل بروفايل طالب" بقت تعرض الكود و QR فوراً بعد البحث.
- خانة "رقم الطالب" اختيارية في إنشاء الطالب والتعديل.

### 3) الحضور والغياب
- تبويب "🚫 الغائبين": بيتجدد يومياً، بيوضح حالة الرسالة (تم الإرسال / لسه). فيه فحص تلقائي كل دقيقة (`setInterval`) طول ما لوحة الأدمن مفتوحة بيكتشف أي طالب فات معاده بـ 15 دقيقة، ولو معاه أكتر من مجموعة لنفس المدرس النهاردة بينتظر لحد آخر معاد بينهم.
- كارت كل مدرس في تبويب "المدرسين" بقى بيوري كام طالب "غايب بعد 3 حصص" معاه.
- **مهم:** زي ما موضح فوق في قسم "بخصوص إرسال واتساب التلقائي"، **مفيش طريقة تقنية 100%** لإرسال واتساب بدون أي ضغطة من المتصفح (سياسات المتصفحات بتمنع فتح نوافذ تلقائياً بدون تفاعل مستخدم، وWhatsApp نفسه مفيهوش API مجاني مباشر). اللي حصل هنا هو أقصى أتمتة ممكنة: النظام بيكتشف الغياب ويجهز الرسالة وحيبقى محتاج ضغطة واحدة بس من الأدمن للإرسال الفعلي (فردي أو "إرسال للكل" بالتتابع).

### 4) المصروفات
- قفل خانة تأكيد الدفع: بمجرد الضغط على ✓ بيتقفل الاختيار تماماً ومينفعش يترجع.
- في صفحة الطالب، خانة "المبلغ" في الدفع الأونلاين بقت مجمدة (readonly) وبتتحدد تلقائياً حسب المادة المختارة.
- تبويب "سجل المصاريف" (داخل الإعدادات): بيجمع كل المدفوعات (عادي + أونلاين) للشهر الحالي مع الإجمالي، وبيعمل أرشفة تلقائية لأي شهر سابق أول ما يتفتح في شهر جديد (`financeArchive/{month}`) وبيبدأ عد الشهر الجديد من الصفر.

### 5) الإعدادات (تبويب جديد ⚙️)
- تبديل لغة أساسي (اتجاه الصفحة RTL/LTR) - ملحوظة: ده بنية تحتية للتبديل مش ترجمة كاملة لكل نص في الموقع، لو عايز ترجمة كاملة لكل الواجهة محتاج شغل إضافي على كل النصوص الثابتة في الـ HTML.
- رفع/تغيير لوجو وخلفية للوحة الأدمن ولصفحة الطالب بشكل منفصل، ولون الشريط العلوي، والوضع الليلي/المضيء - كل ده بيتخزن في `settings/admin` و `settings/student` وبيتطبق فوراً.

### 6) أدوات إدارية
- زرار "حذف شامل لكل بيانات النظام (إعادة ضبط المصنع)" - بيمسح الطلاب والمدرسين والغائبين وسجلات المصاريف والشكاوى والإحصائيات بالكامل، وبيحتاج كتابة كلمة "حذف" في نافذة تأكيد مخصصة قبل التنفيذ.
- نافذة بحث وحذف طالب معين بالاسم/الكود/رقم الطالب.
- مولّد حسابات وهمية للاختبار (يوضع عدد ويتولدوا فوراً، وبيتحطلهم `isTestAccount: true` عشان تقدر تميزهم/تفلترهم لو حبيت).
- صندوق شكاوى واستفسارات: زرار شات عائم (💬) في صفحة الطالب، وتبويب "📮 الشكاوى والاستفسارات" في لوحة الأدمن للرد. المحادثات بتتحذف تلقائياً بعد 24 ساعة من آخر رسالة (الفحص بيحصل كل ما لوحة الأدمن تتفتح).
- رابط LinkedIn في فوتر لوحة الأدمن (غيّر الرابط الموجود بحسابك الحقيقي في `admin.html`).

### تحديث مطلوب على Realtime Database Rules
زود القواعد دي فوق اللي موجودة أصلاً (من غير ما تشيل حاجة قديمة):

## ⚠️ حدود معروفة (Known Limitations)
- **الإرسال الآلي 100% لواتساب وللغياب بدون فتح لوحة الأدمن أصلاً**: محتاج Firebase Cloud Functions + WhatsApp Business API مدفوع (Twilio/Meta) + Cloud Scheduler. النظام الحالي بيكتشف وبيجهز كل حاجة تلقائياً لكن آخر ضغطة إرسال لازم تكون من المتصفح.
- **الترجمة الإنجليزية**: البنية التحتية (تبديل الاتجاه واللغة) جاهزة، لكن ترجمة كل نص ثابت في الصفحات محتاجة شغل إضافي لاحق لو عايز الموقع يبقى ثنائي اللغة بالكامل فعلياً.

## 🆕 التحديث الثاني: بصمة الوجه + واتساب (تلقائي + يدوي مع حالة واضحة)

### 1) بصمة الوجه (Face Recognition) 🙂
بيشتغل بمكتبة **face-api.js** (مفتوحة المصدر، مبنية على TensorFlow.js) وكل التحليل بيحصل **جوه متصفح الأدمن نفسه** - مفيش أي صورة أو فيديو بيترفع لأي سيرفر خارجي. اللي بيتخزن في قاعدة البيانات هو بس "الوصف الرقمي" للوجه (مصفوفة من 128 رقم `faceDescriptor`) ومينفعش ترجعه لصورة تاني.

- **تبويب "إنشاء طالب"**: بعد بيانات الطالب، فيه صندوق "بصمة الوجه (اختياري)" - تشغّل الكاميرا، توجّه وجه الطالب، تضغط "التقاط وتسجيل"، وبيتحفظ مع باقي بيانات الحساب.
- **تبويب "تعديل بروفايل"**: بيوريك فوراً لو الطالب معاه بصمة وجه مسجلة قبل كده ولا لأ، وتقدر تلتقط بصمة جديدة تستبدل بيها القديمة وقت ما تحب.
- **تبويب "الحضور والانصراف"**: زرار جديد "🙂 تشغيل كاميرا بصمة الوجه" بجانب كاميرا QR (الاتنين ما يشتغلوش مع بعض في نفس اللحظة). بيدور تلقائياً كل ~1.2 ثانية على أي وجه قدام الكاميرا، ولو لقى تطابق مع طالب مسجل بصمته (بدقة قريبة كفاية) بيسجله حضور/انصراف زي بالظبط لو كان مسح QR أو كتب الكود.
- محتاج تفعيل صلاحية الكاميرا من المتصفح (زي كاميرا الـ QR بالظبط)، وأول مرة بيحمّل نماذج الذكاء الاصطناعي من الإنترنت (حجم صغير نسبياً، بيتم تخزينها مؤقتاً في المتصفح بعد أول تحميل).
- **ملحوظة دقة**: التعرف على الوجه مش بديل 100% عن التحقق الرسمي (زي أي نظام بصمة وجه تجاري بسيط) - في إضاءة ضعيفة جداً أو تشابه قوي بين الوجوه ممكن يحصل خطأ تصنيف، فالكود والـ QR لسه موجودين كخيار بديل/احتياطي دايماً.

### 2) إرسال الواتساب: "تلقائي + يدوي" مع حالة واضحة جنب الزرار 📱
كل مكان في اللوحة بيبعت رسالة واتساب (تسجيل حضور/انصراف، تأكيد دفع، الغائبين، فاتهم معادهم، الملاحظات) دلوقتي بيظهرله عنصر موحّد:
- بيحاول يبعت الرسالة **تلقائياً** فور حدوث الإجراء (بيشتغل غالباً لو تم فتحه مباشرة من حدث ضغطة زرار، حسب سياسة المتصفح).
- في كل الأحوال فيه **زرار يدوي "📱 إرسال واتساب"** جاهز جنبه على طول.
- وأهم حاجة: جنب الزرار بتلاقي نص واضح إما **"✅ تم إرسال الرسالة لولي الأمر"** (تلقائي أو يدوي) أو **"⏳ لم يتم الإرسال بعد - اضغط الزرار"**، عشان الأدمن يبقى عارف بالظبط إتبعتت ولا لأ ومايبعتهاش تاني غلط.
- لو ضغطت الزرار تاني بعد ما تبعتت، بيتحول لـ"🔁 إعادة الإرسال" - يعني تقدر تبعتها تاني براحتك لو حبيت من غير أي التباس.

### 🗂️ إضافة على هيكل البيانات
```
students/{code}/faceDescriptor   ← مصفوفة 128 رقم (وصف رقمي للوجه) أو null لو مش مسجل
```
مفيش أي تعديل مطلوب على Realtime Database Rules بخصوص التحديث ده (بيتخزن جوه نفس مسار `students/{code}` الموجود أصلاً).

### ⚠️ حدود إضافية
- إرسال الواتساب **التلقائي الكامل بدون أي ضغطة إطلاقاً** برضو محكوم بنفس القيد التقني الأساسي: المتصفحات بتمنع فتح نوافذ جديدة تلقائياً في حالات كتير (خصوصاً لو الإجراء جه بعد `await` أو من مؤقّت زمني `setInterval` زي كشف الغياب التلقائي) - في الحالة دي هيفضل الزرار اليدوي هو الطريقة المضمونة، لكن الحالة "تم الإرسال / لسه" هتفضل واضحة قدامك دايماً.
- بصمة الوجه بتحتاج اتصال إنترنت أول مرة بس (لتحميل نماذج التعرف)، وبعدها بتفضل شغالة حتى لو الإنترنت بطيء نسبياً.

## 🆕 التحديث الرابع: إصلاحات جوهرية + أصوات وشارات تنبيه

### 1) سبب اختفاء طلبات الدفع الأونلاين (وإصلاح مشابه لعدادات الزيارات)
السبب الجذري: الكود كان بيستخدم `orderByChild("status").equalTo("pending")` لجلب طلبات الدفع المعلقة، وده محتاج فهرس (`.indexOn`) متظبط بالظبط في Database Rules الفعلية بتاعتك على Firebase Console. لو الفهرس مش متظبط (وهو غالباً كان كده)، الطلبات كانت بتختفي بصمت من غير أي رسالة خطأ. **الحل**: النظام دلوقتي بيجيب كل البيانات ويفلترها جوه المتصفح نفسه - مش محتاج أي فهرس خالص، هيشتغل مهما كانت الـ Rules عندك. نفس الإصلاح اتعمل لعداد "آخر 24 ساعة" وحساب "سجل المصاريف".

### 2) إجمالي المحصّل هذا الشهر
كل قيمة مبلغ بقت بتتحول بشكل صريح لرقم فعلي (`parseFloat`) قبل الجمع، وأي مبلغ من طلب دفع أونلاين بيتوافق بيتسجل كرقم صريح في نفس اللحظة، فمفيش احتمال يفضل "نص" (string) يمنع الجمع الصحيح.

### 3) "تسجيل الطالب في كل مجموعات المدرس"
الزرار دلوقتي بينشئ صف مادة مستقل ومكتمل البيانات (الاسم/الأيام/الميعاد/المصاريف) لكل مجموعة من مجموعات المدرس بشكل صريح ومباشر، بدل الاعتماد على محاكاة ضغطة تلقائية كانت بتسبب تسجيل مجموعة واحدة بس أحياناً.

### 4) أصوات التنبيه 🔔
بيتشغل صوت تلقائي عند: تسجيل حضور/انصراف (بأي طريقة: كود، QR، بصمة وجه)، تأكيد دفع مصروفات (عادي أو أونلاين)، وإنشاء حساب طالب جديد. من تبويب الإعدادات تقدر ترفع صوت مخصص بصيغة صوتية عادية (mp3/wav)، أو تسيبه فاضي وهيشتغل صوت "بيب" بسيط افتراضي مبني بالكامل في المتصفح (Web Audio API) من غير أي ملف خارجي.

### 5) شارات الأعداد الحية (Notification Badges)
فوق أيقونات "المصروفات" (عدد طلبات الدفع الأونلاين المعلقة)، "الغائبين" (عدد اللي لسه ما اتبعتلهمش تنبيه اليوم)، و"الشكاوى والاستفسارات" (عدد المحادثات اللي محتاجة رد) - بتتحدث لحظياً زي أي تطبيق فيه إشعارات. ملحوظة: تبويب "الملاحظات" مالوش شارة لأنه مفيهوش مفهوم "غير مُراجَع" أصلاً في تصميم النظام الحالي (كل ملاحظة بتتبعت فوراً وقت كتابتها).

### 🗂️ إضافة على هيكل البيانات
```
settings/systemConfig/notifySound   ← صوت التنبيه المخصص (Base64) لو الأدمن رفع واحد
```
مفيش أي تعديل مطلوب على Realtime Database Rules - كل الإصلاحات دي شغالة بأي Rules موجودة عندك حالياً، وفعلياً بقيت الرولز أبسط من الأول لأنها مش محتاجة `.indexOn` خالص.

## 🆕 التحديث الخامس: الغائبين + إعادة ضبط المصنع

### 1) قسم الغائبين
- **تحديث تلقائي كل 24 ساعة**: القائمة بقت مشتركة (realtime listener) في مسار اليوم الحالي مباشرة، وبما إن المسار مبني على تاريخ اليوم، أي تغيير في التاريخ بيتحول الاشتراك تلقائياً لليوم الجديد (الفاضي) بدون أي تدخل أو إعادة تحميل للصفحة.
- **حذف تلقائي عند الحضور**: بمجرد ما الطالب يسجل حضوره (بالكود، الباركود، أو بصمة الوجه - أي طريقة) بيتشال فوراً من قائمة الغائبين لو كان موجود فيها.
- **زرار "حذف الكل"**: بجانب "إرسال للكل" - بيمسح كل قائمة غائبين اليوم دفعة واحدة بعد تأكيد.

### 2) الحذف الشامل (إعادة ضبط المصنع)
الزرار بقى اسمه "حذف شامل لكل بيانات النظام" وبيمسح فعلياً: الطلاب، المدرسين، الغائبين (كل التواريخ)، طلبات الدفع الأونلاين، سجل المصاريف وأرشيفه، محادثات الشكاوى، والإحصائيات (الزيارات والمتصلين الآن) - مش بس الطلاب زي الأول. الحماية من الحذف بالغلط بقت نافذة تأكيد حقيقية (Modal) لازم تكتب فيها كلمة "حذف" بالظبط قبل ما زرار التنفيذ يشتغل، بدل الاعتماد على `confirm()` بسيط ممكن يتضغط بسرعة بالغلط. **ملحوظة**: إعدادات الثيم/الألوان/اللوجو وإعدادات الواتساب مش بتتمسح، لأنها إعدادات موقع مش بيانات طلاب.

### 3) شارات الأعداد الحية
كانت شغالة فعلياً من التحديث اللي فات (بتتحدث تلقائي فور تحميل الصفحة بدون الحاجة لدخول التاب)، وتم كمان إصلاح باگ كان ممكن يخلي شارة "الغائبين" تفضل واقفة على نفس اليوم اللي فتحت فيه لوحة الأدمن أول مرة بدل ما تتجدد كل 24 ساعة زي باقي القائمة.

## 🆕 التحديث السادس: كارت الطالب (Front/Back) جاهز للطباعة

كارت وجه وظهر بهوية سنتر العلا، بيظهر في نافذة منبثقة عند إنشاء طالب جديد ("عرض وطباعة كارت الطالب" في نتيجة الإنشاء) أو من تبويب "تعديل بروفايل" بعد البحث عن الطالب.

- **الوجه**: خلفية تدرج أزرق داكن، اسم السنتر، بيانات الإدارة، رقمين تواصل، والعنوان - كل دي قابلة للتعديل من تبويب الإعدادات → "بيانات كارت الطالب" (مش هاردكود جوه الكود).
- **الظهر**: اسم الطالب وصفه (بيتغيروا تلقائياً حسب الطالب)، التعليمات الثلاثة المطلوبة، QR كود بيوديك لبروفايل الطالب أونلاين، وباركود شريطي (CODE39) بكود الطالب محاط بنجمتين تلقائياً زي الكارت الأصلي.
- **اللوجو**: الكارت بيستخدم نفس آلية اللوجو المرفوع من الإعدادات (Settings → لوجو لوحة الأدمن)؛ لو مفيش لوجو مرفوع بيظهر بديل نصي بسيط. لأفضل نتيجة ارفع صورة اللوجو الحقيقي من هناك.
- **الطباعة**: زرار "طباعة الكارت" بيستخدم `@media print` لضبط الكارت على المقاس القياسي **85.6mm × 53.9mm** بالظبط (نفس مقاس أي كارت ID عادي)، وبيخفي كل عناصر الصفحة التانية وقت الطباعة، والوجه والظهر بيطبعوا على صفحتين منفصلتين متتاليتين جاهزين للقص مباشرة.

### 🗂️ إضافة على هيكل البيانات
```
settings/systemConfig/cardManagerName   ← اسم الإدارة الظاهر على الكارت
settings/systemConfig/cardAddress       ← العنوان الظاهر على الكارت
settings/systemConfig/cardPhone1        ← رقم تواصل 1
settings/systemConfig/cardPhone2        ← رقم تواصل 2
```

## 🆕 التحديث السابع: إصلاح تكرار مصروفات المجموعات المتعددة لنفس المدرس

### المشكلة
لما الطالب يتسجل في أكتر من مجموعة لنفس المدرس (مثلاً 3 مواعيد مختلفة عند "محمد نصار" - كيمياء)، كل مجموعة كانت بتتخزن كمادة منفصلة ليها نفس اسم المدرس، فكانت المصروفات بتظهر وتتحسب 3 مرات بدل مرة واحدة.

### الحل: تجميع حسب المادة/المدرس (Billing Groups)
دالة جديدة مشتركة `getBillingGroups()` بتجمع كل مجموعات نفس المدرس (باستخدام `teacherId`) في "مادة فوترة" واحدة، وبتتطبق دلوقتي في كل مكان بيتعامل مع المصروفات:

- **بوابة الطالب (تبويب المصروفات)**: "إجمالي مصاريف الشهر" و"عدد المواد المشترك بها" بيتحسبوا على المواد الفريدة بس، وقائمة "حالة كل مادة" بتظهر المادة/المدرس مرة واحدة بمبلغه الصحيح.
- **لوحة الأدمن (تبويب المصروفات)**: نفس الشيء - كل مادة/مدرس بتظهر مرة واحدة، وبيتكتب جنبها لو فيها أكتر من مجموعة مرتبطة ("3 مجموعات مربوطة - بتتحسب مرة واحدة") للشفافية.
- **زرار "✓ تأكيد الدفع"**: دلوقتي بيطبّق حالة الدفع تلقائياً على **كل** المجموعات المرتبطة بنفس المدرس لنفس الشهر دفعة واحدة (مش مجموعة واحدة بس)، وكذلك زرار "✗" بيلغي الدفع عن كلهم مع بعض.
- **الدفع الأونلاين**: قائمة اختيار المادة في مودال الدفع بقت بتعرض مادة/مدرس واحد بدل تكرار المجموعات، وموافقة الأدمن على الطلب بتأكد دفع كل المجموعات المرتبطة تلقائياً.
- **سجل المصاريف (Finance Ledger) وعداد "غير دافعين"**: اتصلحوا كمان عشان محتسبوش نفس المبلغ 2 أو 3 مرات لنفس الطالب.
- **بوابة الحضور**: رسالة "لسه ما دفعش" بتظهر اسم المادة/المدرس مرة واحدة بدل ما تتكرر لكل مجموعة.

**ملحوظة**: لو فيه فرق بسيط في المصاريف بين مجموعات نفس المدرس (حالة نادرة)، النظام بياخد أعلى قيمة تلقائياً تجنباً لنقص التحصيل.

### 🔧 إصلاح إضافي (نفس البند): تجميع المواد المضافة يدوياً بدون ربط مدرس
اتضح إن في حالات كتير المادة بتتضاف يدوياً (من غير اختيار مدرس/مجموعة من القايمة الجاهزة)، فمش بيتسجل لها `teacherId` خالص، وكان التجميع بالمعرّف ده بس مش كافي. دلوقتي النظام بيجمع كمان حسب "الاسم الأساسي" للمادة - يعني الجزء اللي قبل أول " - " في الاسم. يعني لو كتبت "كيمياء محمد نصار - 3:00ص" و"كيمياء محمد نصار - 4:00ص" هيتجمعوا صح كمادة واحدة، لأن الجزء قبل الشرطة متطابق.

**⚠️ عشان التجميع يشتغل صح مع المواد المُضافة يدوياً**: خلّي الجزء اللي قبل أول " - " في اسم المادة **ثابت ومتطابق** لنفس المدرس (زي "كيمياء محمد نصار")، والتفاصيل المختلفة (الوقت، رقم المجموعة) تحطها بعد الشرطة. لو استخدمت زرار اختيار المدرس والمجموعة من القايمة الجاهزة، الاسم بيتظبط تلقائياً صح من غير أي تدخل.

## 🆕 التحديث الثامن: إدارة البيانات والتصدير (PDF + نسخة احتياطية JSON)

قسم جديد في تبويب الإعدادات → "📤 إدارة البيانات والتصدير" فيه ثلاث أدوات، ملف جديد `js/data-export.js`.

### 1) تصدير تقرير شامل (PDF)
**ملحوظة تقنية مهمة**: مكتبات زي jsPDF/jspdf-autotable مفيهاش دعم حقيقي للغة العربية (مفيش "Arabic shaping" - يعني ربط الحروف ببعض - غير لو اتضمّن خط عربي خاص بشكل معقد جداً)، والنتيجة عملياً بتطلع حروف عربي منفصلة أو مقلوبة أو مربعات فاضية. **الحل المستخدم هنا (نفس أسلوب طباعة كارت الطالب بالظبط)**: بناء تقرير HTML منسّق زي أي صفحة في الموقع، وبعدين استخدام **طباعة المتصفح** (زرار "🖨️ طباعة / حفظ PDF" بيفتح نافذة الطباعة، واختار منها "Save as PDF") - كده النص العربي بيطلع سليم 100% لأنه نفس عرض المتصفح العادي، مش رسم فونت يدوي.

التقرير بيغطي: ملخص عام (عدد الطلاب/المدرسين/المحصّل الشهري/الغائبين/الطلبات المعلقة)، قائمة كل الطلاب، المدرسين ومجموعاتهم، سجل مصاريف الشهر الحالي، طلبات الدفع الأونلاين المعلقة، حضور وانصراف اليوم، الغائبين اليوم، وإعدادات النظام. **ملحوظة**: التقرير بيعرض حضور "اليوم" بس (مش كل تاريخ الحضور من الأول) عشان يفضل تقرير قابل للقراءة والطباعة الفعلية - السجل الكامل لكل يوم موجود بالكامل في النسخة الاحتياطية (JSON) بدون أي حذف.

### 2) تصدير نسخة احتياطية كاملة (JSON)
بيجيب كل العُقد المعروفة في التطبيق (`students`, `teachers`, `absentees`, `paymentRequests`, `financeArchive`, `supportChats`, `stats`, `settings`, `presence`) بالكامل من غير حذف أي حقل، وبيحملهم في ملف واحد بصيغة:
```json
{ "exportedAt": "...", "appName": "Al Ola Center", "schemaVersion": 1, "data": { "students": {...}, "teachers": {...}, ... } }
```
الملف ده جاهز لنقل قاعدة البيانات بالكامل لمشروع Firebase تاني أو دومين تاني (تستورده من نفس زرار "استعادة نسخة احتياطية").

### 3) استعادة نسخة احتياطية (Import JSON)
بترفع الملف، والنظام بيتعرف تلقائياً على الأقسام الموجودة فيه ويوريهالك في نافذة تأكيد قبل أي تنفيذ (لازم تكتب كلمة "استعادة" بالظبط زي نظام الحذف الشامل). الاستيراد بيدعم كمان الصيغة اللي بيطلعها زرار "Export JSON" المدمج جوه Firebase Console نفسه مباشرة (بدون الـ wrapper بتاعنا)، مش بس الملف اللي بيطلع من الزرار هنا.

**⚠️ تنبيه**: الاستعادة بتستبدل (`set`) كل عقدة موجودة في الملف بالكامل بمحتواها - أي بيانات حالية في نفس العقدة مش موجودة في الملف المرفوع هتتمسح. لو عايز دمج بدل استبدال كامل، قوللي.

### 4) نسخ احتياطية محفوظة داخل النظام (بدون الحاجة لرفع ملف)
كل مرة تضغط "تصدير نسخة احتياطية كاملة"، بالإضافة لتنزيل الملف على جهازك، بيتحفظ نسخة منها تلقائياً جوه قاعدة البيانات نفسها (`systemBackups/{timestamp}`). تحت زرار الاستعادة هتلاقي قائمة بآخر 5 نسخ محفوظة (بتاريخ ووقت كل نسخة)، وكل نسخة معاها زرار **"♻️ استرجاع"** (بيفتح نفس نافذة التأكيد المعروفة) و**"🗑️"** لحذفها. الأقدم من آخر 5 بيتحذف تلقائياً عشان الحجم ميكبرش من غير داعي.

**⚠️ ملحوظة**: النسخ المحفوظة دي بتتمسح هي كمان لو عملت "حذف شامل/إعادة ضبط المصنع" (زي باقي بيانات النظام تماماً - ده قرار متعمد للبساطة). يعني لو عايز تضمن إمكانية الاسترجاع بعد أي حذف شامل، **لازم يكون عندك ملف JSON نزّلته على جهازك من قبل** من زرار "تصدير نسخة احتياطية"، وترفعه من "استعادة نسخة احتياطية (رفع ملف JSON)" وقتها. لازم تضيف الـ Rule الجديدة بتاعة `systemBackups` من قسم Database Rules فوق قبل ما تستخدم الميزة دي.
